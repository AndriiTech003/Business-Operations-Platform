# FRONTEND · React SPA

## Стек
React 19, Vite, TypeScript strict, TanStack Router (типизированные роуты и search params), TanStack Query, TanStack Table + Virtual, **React Flow** (конструктор), **dnd-kit** (канбан), shadcn/ui + Tailwind, react-hook-form + zod, CodeMirror 6 (редактор выражений с подсветкой и автодополнением), ECharts (отчёты), `@scope/realtime-client` (проект 03), `@scope/flags-react` (проект 02).

## Структура

```text
web/src/
├── app/            # router, providers, layout (sidebar, topbar, ⌘K), auth
├── lib/            # api-клиент (из OpenAPI), realtime, flags, format (money/date), query keys
├── components/     # общие: DataTable, RecordHeader, Timeline, CustomFieldInput, UserPicker, EmptyState…
└── features/
    ├── companies/  contacts/  deals/  invoices/  tasks/
    ├── workflows/  # список, конструктор, запуски, шаблоны
    ├── approvals/  # «Inbox» одобрений (workflow + AI-агент)
    ├── reports/
    ├── notifications/
    └── settings/   # команда, роли, кастомные поля, воронки, email-шаблоны, API-токены, секреты
```

## Ключевые экраны

### 1. Записи (companies / contacts / deals / invoices)
- **DataTable**: виртуализация, выбор колонок (включая кастомные поля), фильтры-«чипы» (поле / оператор / значение), сохранённые представления, сортировка, bulk-действия, inline-редактирование ячеек с optimistic update.
- Состояние таблицы (фильтры, сортировка, колонки) хранится в URL search params (TanStack Router валидирует их zod-схемой) → ссылкой на представление можно поделиться.
- **Страница записи**: шапка с ключевыми полями (редактирование на месте), вкладки: Overview, Activity timeline (звонки, письма, заметки, изменения полей, действия workflow и агента с разными иконками), Tasks, Related (сделки компании, счета), Comments с @упоминаниями.
- **Presence**: аватары «сейчас смотрят» на записи и мягкая блокировка («Anna редактирует сумму») — через realtime-канал записи.
- Конфликт (`412`): диалог с diff «ваше / сохранённое».

### 2. Канбан сделок
- Колонки = стадии, карточки с суммой, владельцем и днями в стадии; сумма и взвешенная сумма в шапке колонки.
- Drag-n-drop (dnd-kit) с клавиатурной доступностью; порядок — дробный индекс (`position` между соседями), поэтому перемещение = 1 запрос.
- Optimistic перемещение + откат при ошибке; изменения других пользователей прилетают через realtime и анимируются.
- При перемещении в `lost` — модалка причины.

### 3. Счета
- Редактор с позициями (динамические строки, пересчёт сумм и налогов на лету, деньги — только целые центы), превью PDF рядом (iframe HTML-шаблона).
- Отправка: модалка с превью письма → Idempotency-Key.
- Публичная страница счёта для клиента (без авторизации, по токену), кнопка «Mark as paid» в демо.

### 4. Конструктор workflow (главный экран для демо)
- **Холст React Flow**: узлы с иконками по типу, рёбра с метками (`true` / `false` / `approved` / `timeout` / `error`), автолэйаут (elkjs) по кнопке, мини-карта.
- **Палитра узлов** слева (drag на холст), **панель свойств** справа: форма `config` генерируется из схемы узла (реестр из `workflow-core`).
- **Поля-выражения** — CodeMirror с подсветкой синтаксиса, **автодополнением из контекста типов** (`invoice.` → список полей с типами, включая кастомные и `steps.X.output`), ошибками типов с подчёркиванием в реальном времени. Парсер и type checker — тот же пакет `packages/expr`, работает в браузере.
- **Валидация** при каждом изменении: проблемные узлы подсвечены, список проблем внизу с переходом к узлу.
- **Draft / Publish**: автосохранение черновика (debounce), Publish → diff с активной версией (добавленные / удалённые / изменённые узлы) → подтверждение.
- **Test run**: выбрать запись или вставить payload → запуск в тестовом режиме → статусы узлов обновляются на холсте в реальном времени.
- **Undo/redo** (история изменений графа), копирование и вставка узлов, горячие клавиши.
- **Галерея шаблонов** при создании.

### 5. Запуски workflow
- Таблица запусков (статус, версия, триггер, длительность), фильтры.
- **Replay на графе**: тот же холст в режиме только чтения; узлы окрашены по статусу (succeeded / failed / waiting / skipped), на рёбрах — какой путь пройден. Клик по узлу → input, output, ошибка, попытки со временем, idempotency key.
- Действия: Retry failed step, Cancel run, «Open test run in builder».
- Ожидающие шаги показывают «сработает через 2д 4ч» или «ждёт одобрения от: …».

### 6. Approvals inbox
- Общий для workflow и AI-агента (проект 06): карточка с заголовком, контекстом (запись, сумма), превью действия (письмо, изменение полей), кнопки Approve / Reject с комментарием, дедлайн.
- Бейдж с количеством в сайдбаре, обновление через realtime.

### 7. Отчёты
- Воронка по стадиям (конверсия между стадиями, среднее время в стадии), выручка по месяцам (закрытые сделки против оплаченных счетов), AR aging (0–30 / 31–60 / 61–90 / 90+), активность команды. Фильтры по периоду и владельцу.

### 8. Settings
- Кастомные поля: конструктор (тип, опции select, required, indexed), drag-n-drop порядок.
- Воронки и стадии, email-шаблоны (редактор с переменными и превью), роли, API-токены, секреты (значение показывается один раз).

## Паттерны
- Query keys factory, optimistic updates, инвалидация по realtime-событиям (`record.updated` → `invalidateQueries(keys.deals.detail(id))`, без полного refetch списков, если можно обновить кэш через `setQueryData`).
- Фичи за флагами (`@scope/flags-react`), например новый конструктор или `ai_step`.
- Error boundaries по панелям, skeleton-состояния, пустые состояния с действиями.
- Доступность: клавиатура в канбане и таблицах, фокус в модалках и панелях.
- Тесты: Vitest + Testing Library (DataTable-фильтры, редактор счёта, панель свойств узла), Playwright (сценарии ниже).

## E2E-сценарии (Playwright)
1. Создать компанию, контакт, сделку → перетащить сделку в `won` → workflow «Deal won» создал задачи и черновик счёта (видно в timeline).
2. Собрать в конструкторе workflow из шаблона «Overdue invoice», изменить условие (с автодополнением), опубликовать → счёт с прошедшим сроком → письмо в Mailpit → задача создана.
3. Approval: workflow доходит до одобрения → менеджер одобряет в inbox → финальное письмо.
4. Два браузера: перемещение сделки в одном появляется в другом.
